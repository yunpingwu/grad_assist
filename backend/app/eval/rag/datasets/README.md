### 为什么「去重 gold」会少于题数

因为**同一个 chunk 可以是多道题的 gold**。每道题都至少有 1 条 gold，所以「gold 引用」一定不小于题数；但两题共用一个 chunk 时，「去重 gold」就掉一格。全局 322 次引用收敛到 302 个 chunk，差 20 —— 就是下面这 20 处：

| 数据集 | 共用的题目（皆为两题共用同一个 chunk） |
| --- | --- |
| `c`（2 处） | C2-001 + C2-018；C2-007 + C2-008 |
| `ds`（4 处） | DS2-004 + DS2-016；DS2-006 + DS2-025；DS2-013 + DS2-014；DS2-034 + DS2-035 |
| `db`（8 处） | 006+007；012+013；019+023；020+021；027+030；028+029；032+034；041+042（前缀 `DB-20260916-`） |
| `net`（6 处） | 002+003；021+022；034+035；037+038；039+040；041+042（前缀 `NET-20260916-`） |
| `os` / `co` | 无 |

抽查过全部 20 处：**没有重复题**，都是同一段正文的不同侧面或不同实例（例如 NET-039 问 TCP 半关闭时 B 能否继续发数据、NET-040 问主动关闭方为何等 2MSL，两题都落在「TCP 连接释放」那一节；DS2-013 问顺序表/链表的优缺点、DS2-014 问顺序表插入为何要搬元素，同属「线性表的存储结构」）。有几对角度更接近（DS2-004/016、DS2-006/025、NET-034/035），但都是独立问句。

**读报告时要知道的两件事**：

1. **300 题不是 300 个独立样本**。共享 gold 的两题在召回指标上同起同落——那个 chunk 检索对了两题一起对。20 对占 13%，做配置间比较影响很小，但**不要拿它做显著性推断**。
2. **被共用的段落被加权两次**。按章节聚合指标时，这些小节贡献了两份。

要消掉这层相关性，方向是合并同段落的题目、或给每题补独立证据；本轮不动，先记在这里。

## 这些文件只装题集，不装答案

**`response` 和 `retrieved_chunk_ids` 不在数据集里**——它们是某个检索配置下的产物，落在
[`../samples/<配置>/`](../samples/)（见那边的 README）。数据集保持「config 无关」：换配置
换的是样本，题集一个字不动。

当前所有集合的 `revision` 为 `2026-10-16.2`（`.1` 是格式统一，`.2` 是答案字段移出前的最后修订）。

## gold_contexts/

每题 `gold_chunk_ids` 指向的 chunk 正文，从 Milvus 全量转储
（`data/eval/chunks/<collection>.json`，8.7MB，不入库）里按 id 抽出。评测侧
`reference_contexts` 一律从这里取。

**自校验**：chunk id 末段是 `sha1(归一化正文)[:12]`（见 `app/textbook_flow/chunk_id.py`），
所以每一条 gold 正文都能重算哈希与 id 对账——不需要 Milvus、也不需要那份全量转储，
就能证明正文没被改过。迁移时 302 条全部通过。

## 入库与再生成

- `*.json`（题集）与 `gold_contexts/*.json`（gold 正文）**都入库**。
- 全量 chunk 转储不入库，需要时用 `python -m app.eval.retrieval.dump_chunks` 重新生成。
- 题集改动请**递增 `revision`**（`<YYYY-MM-DD>.<n>`）；教材重新摄入导致 gold 正文变化时，
  必须重跑 gold_contexts 抽取并确认自校验通过。

## 迁移出处

由 `scripts/unify_eval_sets.py`（一次性脚本）从 `data/eval/<教材>/qa_set.json` 生成：
裁掉常量与作者期脚手架字段、删除语料副本 `gold_evidence`、`category` 重映射为 5 类统一词表。
